# Juniper 1 adaptation: data record

Date: 2026-10-04. This record covers every data source used by
`aaa.erudition.v0` and every candidate source that was inventoried and not
used.

## Used

| Source | Origin | Licence | Privacy | Content | Use | Identity | Allowed splits |
|---|---|---|---|---|---|---|---|
| ToolShift episodes | generated by `toolshift.py` from stream identities | Apache-2.0 (this repository) | synthetic; no personal data | workspace states, templated requests, scheduled shifts, templated feedback | training (train split only), development, attack, confirmation | protocol `aaa.erudition.v0`; spec file hash in the source fingerprint | name and alias vocabularies are disjoint by split (tested); confirmation streams exist only after admission |
| gpt-oss-20b MXFP4 GGUF | OpenAI `openai/gpt-oss-20b` @ `6cee5e81…`, converted by the Juniper LM 1.1 qualification | Apache-2.0 plus OpenAI's gpt-oss usage policy | no user data | the immutable base Language Model | inference only; never trained | SHA-256 `9d7364f0…d23d`, 12,109,566,784 bytes | all, unmodified |
| GPT-OSS backend profile | `Cinqic-Research/Juniper-App` `config/backends/gpt-oss-20b.json` @ `11225ba` | Juniper-App licence | none | runtime and sampler configuration | runtime parameters | SHA-256 `be1e052a…353a`, recorded in `data/gpt_oss_profile.json` | all |
| Real-model characterization transcripts | GPT-OSS answering training-split situations (`characterize.py`) | generated here | synthetic prompts; no personal data | requests, tool calls, token log-probabilities | fitting the simulation surrogate's rates only | call-cache entries keyed by request SHA-256; the fitted parameters record the characterization files' hashes | train split only |
| Real-model run transcripts | GPT-OSS during development, attack and confirmation runs | generated here | synthetic | as above | evaluation evidence; never training data | per-run call caches with the run outputs | the split of the run |
| Simulated training streams | `simulate.py` with the surrogate | generated here | synthetic | evidence features, counterfactual returns, regime labels | Erudition Model training | file SHA-256 recorded in each model's metadata | train split only |

The real-model transcripts contain the model's reasoning text for synthetic
tasks. Juniper-App never stores reasoning for user conversations. These
records involve no user and are kept for exact replay and audit.

## Inventoried and not used

| Source | Why not |
|---|---|
| Cinqic History Dataset (`cinqic.history.v1`, HDD) | Not relevant to the adaptation signal studied here. It also contains founder statements and assistant memories, and its 1.1.0 candidate is marked "NOT APPROVED" for training-data distribution. |
| JuniperBench and other held-out evaluation suites | Never used for training. No JuniperBench claim is made. |
| AAA historical evidence (dot era, `aaa.python.v0`/`v1`, `aaa.wm.*`) | Informs methodology only (causal boundary, freezes, recomputation). It is not training data and no earlier result is reinterpreted. |
| Earlier AAA weights (Champion 0/1, Python learners, WM-S tables, the 5.2M language model) | Forbidden as initialization; the Erudition Model is trained from scratch. |
| Juniper LM 1 (GPT-2 124M study, retired 2026-10-04) and other retired Cinqic model research | Not components of Juniper 1; no weights or outputs used. |
| Juniper-App user memories, conversations, credentials | Not read and not trained on. Erudition training memory and Juniper user memory are separate concepts ([architecture](architecture.md#memory-ownership)). |
| Other HDD contents (GPT-2 experiments, model caches, signing material, recovery codes) | Unrelated and, in places, private. Nothing on the HDD outside this work's data root was read for training or uploaded anywhere. |

## Contamination controls

- **Splits.** Every stream identity is `(split, index)`. Names and aliases are
  disjoint across `train`, `development`, `attack` and `confirmation`
  (tested). Templates are shared, so they are part of the task, not its
  answer.
- **Admission.** `make_stream("confirmation", …)` raises `AdmissionError`
  unless the caller passes the admission granted by the committed freeze.
  Confirmation streams were not generated before the freeze.
- **Training data.** The surrogate's rates and the simulated training streams
  use the train split only. Development results tuned the heuristic control
  and the integration contract (documented in D-3 and the controller's
  docstring); the attack split is reserved for adversarial evaluation.
- **No external compute.** No data or model left FLOWBOX: no cloud GPU, no
  upload and no network call other than the loopback model runtime.
